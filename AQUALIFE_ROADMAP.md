Правила игры и список нерешённых вопросов находятся в [AQUALIFE_RULES.md](./AQUALIFE_RULES.md). Архитектурные и производительные требования описаны в [GAME_ENGINE_RULES.md](./GAME_ENGINE_RULES.md).

### Реализация этапа 3

- Стабильный ID выбирается из доступных provider-полей `userId`, `id`, `secUid`; `uniqueId` используется только как запасной идентификатор.
- Для событий применяется `dedupeKey` на основе ID провайдера и типа события. Если провайдер не прислал ID, событие не подавляется искусственным ключом, чтобы не потерять настоящие лайки.
- Рыбка индексируется по ID участника: вход, чат, лайки, подписка и подарки обновляют одну сущность, не создавая вторую.
- `hp` хранит текущий HP, `maxHp: null` явно означает отсутствие игрового максимума; сохранены накопленные лайки и остаток порога, базовые и текущие характеристики, вид, баффы и жизненный цикл.
- Никнейм и доступный URL аватарки обновляются при последующих событиях. Визуальный снимок отделён от симуляции, PixiJS получает только данные для отображения.
- Добавлены Node.js-тесты на стабильный ID, отсутствие дублирующей рыбки, повторные события, порог HP, остаток лайков и обновление профиля. GitHub Actions прошёл `typecheck`, тесты и `build`.

### Реализация этапа 4

- Нормализатор проверяет ID участника, длину текстовых полей, timestamp, явное количество лайков и URL аватарки (только HTTP/HTTPS). Доступные nickname/avatar обновляются по мере поступления событий.
- Игровая идентичность использует доступный стабильный ID провайдера; существующий рейтинг и legacy-сообщения сохраняют прежний ключ пользователя.
- Дедупликация выполняется только при наличии ID события от провайдера. События без такого ID не подавляются искусственным ключом, чтобы не терять настоящие повторные лайки.
- Combo-подарки типа 1 не обрабатываются до `repeatEnd`; количество берётся из `repeatCount` или доступных альтернативных полей схемы. Реальные ID подарков и игровые эффекты пока не назначаются без подтверждённой таблицы.
- Очередь ограничена конфигурацией `maxQueuedEvents` и доставляется пакетами. Соседние последовательные пакеты лайков одного участника объединяются в одно событие с суммой количества; при перегрузке сначала отбрасываются лайки, затем чат, чтобы по возможности сохранить подписки, входы и подарки. Существующие обновления чата/рейтинга/подарков остаются отдельными от очереди AquaLife.
- `/health` отдаёт только агрегированные счётчики и не включает ключи подписи или исходные payload. `fishEntitiesExpected` является оценкой по отслеживаемым участникам, а не точным числом живых рыбок: сервер пока не является владельцем состояния симуляции.
- Индивидуальный выход зрителя не выдумывается: пока надёжное событие отсутствует, перевод рыбки под ИИ по выходу не выполняется. Проверка в реальном LIVE и нагрузочный тест остаются необходимыми.

### Реализация этапа 6

- Реализовано движение в логическом мире 540×960, независимом от размеров окна; координаты ограничиваются границами мира с учётом размера рыбки.

### Реализация этапа 7
